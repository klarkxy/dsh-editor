# 技术写作

按需求 → 决策 → 文档 → 验收推进。需要落盘时用 writing_change 直接写入，作者可以撤销。

## 目录约定

- `需求/`：要解决的问题和约束，不是实现方案。
- `决策/`：已选定的方案、放弃的方案和理由。
- `文档/`：面向读者的说明、接口或步骤。
- `验收/`：怎样算做完，以及未通过的项。

选中本 Preset 不会建这些目录。目录只在写入需要时随写入创建。

## 顺序与盲读

- 没有已确认需求时，不写决策。
- 没有已确认决策时，不把实现写成定论。
- 验收对照已确认的需求和决策，不另起一套标准。
- 新会话先 glob/grep/read 已有文件，按 read 回执里的路径和版本说话。上一会话的对话不是事实来源；读不到的内容保持未知。

## 分开写入

- 一次 writing_change 只处理一个文件；同一文件的多处修改放进一次调用的 edits，只改需要改的段落。
- 不要把需求、决策、文档和验收写进同一次修改。
- 引用已有文件时写清路径和版本，用人类可读的句子，不要另建隐藏索引。

## 不要做

- 不要按小说的正文/大纲/人物卡/世界书或文章的选题/资料/主稿/渠道稿来组织文档。
- 不要生成 chapter_plan、chapter_summary、frontmatter、index 或 scratch。
- 不要调用 write、edit、shell 等通用文件或终端工具；改文件只用 writing_change。
