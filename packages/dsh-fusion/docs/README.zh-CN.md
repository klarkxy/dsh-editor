# Fusion 协作

[English](https://github.com/klarkxy/dsh-editor/blob/main/packages/dsh-fusion/README.md)

在宿主的插件设置中启用「Fusion 协作」。插件默认关闭，启用后不需要再为每段对话打开开关。

需要 Node.js ≥22 与兼容的 DSH `0.1.7-rc.2` 宿主。若所用 DSH 发行版未内置本插件，可与 `@klarkxy/dsh-ai-services` 一同通过宿主插件配置启用 `fusion` 入口：

```sh
npm install @klarkxy/dsh-fusion
```

主助手负责讨论、规划与审阅，持久的执笔搭档负责生成候选。每次修订及后续任务沿用同一个搭档会话。通过主助手审阅的文本仍然是候选；只有你在任务卡片上点击「预览采用」并在预览中「确认采用」后，宿主才会校验来源版本和未保存草稿并写入文件。

原文变化时，候选会保留，但不能覆盖新的正文。请保存需要保留的草稿，并让助手基于当前内容重新修订。停止任务或关闭插件不会撤销已经采用的正文。

任务卡片提供当前状态、候选预览、「停止协作任务」和恢复入口。关闭卡片不停止推理。重启后不会自动重发任务；需要核对执行记录后明确恢复。报告已保存但通知未确认时，可重新通知主助手继续审阅，无需重新启动执笔。

模型在首次配对时绑定。共享模型设置中对 Fusion 搭档的修改适用于新配对；已有搭档继续使用原模型。未获得的费用或缓存数据不会被估算成确定值。

原生 Web 使用既有子会话导航和执行记录。通用任务可能已经通过原生工具修改文件，因此「审查通过」不表示仍在等待作者采用。

## Agent 工具

主助手持有五个工具，执笔搭档持有一个汇报工具。工具身份在注册时绑定，每次调用都会再次校验，其他 Agent 无法借用。

主助手（Lead）：

- `fusion_delegate`：把一个有边界的任务委派给同一个持久搭档。写作任务中执笔基于主助手提供的带版本原始目标撰写精确文本；通用任务保留普通执行工具，接管前需显式取消。
- `fusion_read`：读取已保存的精确候选及其哈希；审阅这份内容而不改写。
- `fusion_review`：按候选 id 与哈希审查。accept 仅是模型审查——是否采用仍由作者决定；revise 必须给出具体反馈；reject 结束任务。
- `fusion_decide`：答复搭档的决定请求，或带反馈显式恢复被中断的任务，复用其持久会话。
- `fusion_cancel`：在显式接管前取消本方搭档任务；不影响无关子会话，也不撤销已经写入的文件。

搭档（Sidekick）：

- `fusion_report`：以唯一 reportId 汇报当前任务的精确候选或决定请求；绝不直接写稿，确认后不会重新生成或重复发送。

## 包入口

默认导出注册插件；`./contracts` 导出浏览器安全的公开记录（RPC 通道、工具名、任务与候选类型）；`./host-contracts` 定义宿主侧 `fusionWriting` 端口；`./client` 是浏览器端界面包。
