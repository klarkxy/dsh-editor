# Dream 与 Self Improve：可独立部署的学习边界

## 所有权

Dream 是公开包 `@klarkxy/dsh-memory` 的语境观察与整理能力，不另建一套存储。Self Improve 是公开包 `@klarkxy/dsh-self-improvement` 的行动经验能力。两者只使用 DSH 的会话、生命周期、存储域、RPC、原生 Web 扩展位以及公开的 `@klarkxy/dsh-ai-services`。不得导入 `dsh-editor-*`，不得把 Editor 私有服务作为必需依赖。

Memory 可以不安装 Self Improve；Self Improve 需要明确启用 Memory 作为存储，但不要求开启 Dream。设置页合用原生「记忆」入口，不依赖 Editor shell。关闭 Dream 停止语境观察和闲时整理，不关闭 Self Improve；关闭 Memory 不允许 Self Improve 绕过存储或创建第二套记忆。

## 数据与证据

Dream 维护描述性知识：偏好、项目事实、决策，以及新增的 `vocabulary`、`activity`。Self Improve 只生成 `lesson`，带可选的结构化 `procedure`。共享服务采用增量字段扩展，旧记录无须补造元数据，不自动重新分类历史文本。

`context` 保存 `subject`、`domain`、`key`、`aliases`、`observedAt`、可选的原话时间 `eventTime` 和活动状态。自动记录按原生会话 cwd 隔离，缺失 cwd 时不默认为全局。作者、领域、术语或事项的不同含义不得相互覆盖。`user` 是当前本地用户，`general` 是未指明领域；其他标识和别名必须出现在引用中。多用户身份隔离不由本插件提供。

`procedure` 保存 `origin`（明确要求或结果观察）、`goal`、`when`、`steps`、`avoid`、`verify`，例外继续使用记录的 `exceptions`。方法必须可说明何时适用、做什么以及怎样检查，不能通过降低验收条件或权限检查来制造“成功”。

一句话可产生两条不同记录，共享原始证据。例如“蓝图是事件结构；以后改稿先确认结构”，前半句属于 Dream，后半句属于 Self Improve。人物设定仍由世界书等权威资料维护，Dream 不成为隐形世界书；临时任务要求不升级为永久操作规程。

## Dream 的两种节奏

回合结束时，只观察真实 `user/message` 且 `source.kind=user` 的消息。不把助手自述、工具输出或插件注入当作者发言。首次启用只观察最新消息；后续每次最多取 4 条新消息，每条最多 2000 字符，最多生成 8 条记录。模型输出须包含真实 seq 和逐字引用，身份、别名和时间必须有引用依据。不确定时不写入，不用原文整段作为失败回退。

`memory.observe-context` 使用共享模型路由、预算与取消机制。纯“继续”等确认消息不触发此调用。默认观察模型使用 normal 角色；强模型仍用于低频 Dream 整理。

活动状态默认具有 7 天的新鲜度上限。这不是事实失效日，更不代表任务完成；到期后不自动注入，新的明确报告可以更新。暂停、阻塞、完成等状态只表示上次报告。时间原话与宿主记录时间分开保存，不自动将“周末完成”改成“已经完成”。更新同一事项时，原记录标记 superseded，保留审计历史。

闲时整理仍要求约 15 分钟空闲、24 小时间隔以及至少 3 项变更。整理只在同一范围、类型和语境身份内进行，不把近期状态混进永久词条、不刷新观察时间、不延长来源有效期、不处理 lesson。全部来源均 active 时可产生 active 的替代记录；任何候选来源都保持候选。缺失可引用证据的旧手动记录保留原样，不伪造 seq 或“整理依据”。

持久化观察游标与删除墓碑一起阻止重启后重放旧消息。最多保留 512 个会话游标，达到上限后停止为新会话自动观察，不通过驱逐游标使已删除内容复活。模型等待期间的删除、修订、停用、会话文本或范围变化使结果失效。游标不是第二份会话历史，只保存处理进度。

## Self Improve 的生效规则

明确的人类方法要求在适用范围内直接生效，可撤回。模型概括的工具恢复或正向方法反馈保留为 candidate，采纳后才参与注入。这里的采纳代表用户批准使用，不代表通过了自动化质量证明。

工具恢复必须位于同一人类请求内，具有可比较的明确目标和不同参数。仅同名工具成功、其他文件成功、无目标调用或参数未变的重试都不能形成恢复经验。即使匹配成功，也只叫观察，不叫“已验证修复”。无模型时只保留保守识别出的明确方法要求，不把词义纠正或工具错误日志复制成技能。

程序性检索支持中文片段；用户只说“继续”时先读取未过期、同项目的 activity，再检索适用方法，不依赖插件 Hook 的先后顺序。两种注入仍分别限制为最多 5 条、约 800 tokens，只有 active 记录参与。当前指令、权限和权威资料优先。

Skill 是多条已生效方法的可审阅 Markdown 导出，不是每次反馈自动生成的新文件；不自动安装、不修改 AGENTS.md、不执行脚本。撤回只影响应用内记录，不收回已经下载的文件。

## 回归与限制

核心回归位于 `dsh-memory/src/observe.spec.ts`、`dsh-self-improvement/src/procedure.spec.ts`，覆盖分流、状态时效、项目隔离、证据、删除与停用竞态、候选生效及工具目标关联。原有 CAS、撤回、导出和 RPC 鉴权测试继续保留。

模型对原话含义的概括仍可能出错。逐字引用验证证明来源，不证明解释或方法必然正确。固定模型夹具验证管线和生命周期，不能证明真实小说质量改善。未来评估应分别测语境理解和真实动作结果，并比较两者关闭、单独开启、同时开启四组；不得用生成经验的模型自评分代替验收。

后续 Agent 不应合并两条写入通道、取消候选状态、扩大作用域、将旧日期推断成完成，或用 Editor 私有依赖“修复”独立 Web 的装载问题。
