# 产品原则

这些边界定义产品取舍；改变它们需单独授权。运行时与信任模型见[架构决策](architecture.md)。

## 作者决定内容

作者写正文、决定剧情；模型提供短补全、选段改写、讨论和可预览的文件提案。人物、设定与规划先讨论再采用，冲突交回作者，修改应可恢复。

不做自动批量生成章节，不把生成结果直接灌入文件，也不要求每章结束后填写小结或完成整理流程。

## 作品保持开放

作品是普通文件夹，正文、人物卡、世界书和大纲使用 Markdown / TXT。目录随实际创建文件出现，不预建模板或强制前置表单，不用隐藏数据库定义作品结构。

人物卡和记忆等辅助功能可按需开启，核心写作不依赖它们。旧会话兼容与退出条件由[小说插件](../packages/dsh-editor-novel-kernel/README.md#旧会话兼容)维护。

## 稿纸优先

稿纸保持中央主位、暖色纸面与墨蓝强调色，辅助界面更中性。常用界面文字不小于 13px，主控件不小于 32px，顶栏约 52px。宽度不足时收起辅助栏，不挤压正文。

不采用紫色渐变、玻璃拟态、霓虹 AI 装饰或仅英文界面。不把写作台扩成 IDE：不增加 Git UI、终端、LSP、minimap、activity bar、审阅 gutter 或句内卡片。

## 能力边界

- 不自建第二套 Chat、会话、审批、权限、模型注册或工作流引擎。
- 不引入关系图、向量库、后台索引、卡片拖放、手写摘要、章节与大纲强制绑定，或 `/`、`@` 命令面板。
- 不扩展到 Android、远程多用户或云同步。
- 写作模式不提供终端；开发者模式中的官方 Agent 保留自身工具。

工作流参考过 NarraLume、Linetta、novelWriter 与 Manuskript；不复制 GPL / AGPL 实现。若复用 NarraLume 代码，须另行核对许可证、NOTICE 与具体文件来源。
