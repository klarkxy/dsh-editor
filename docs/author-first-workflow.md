# 作者优先工作流：前置规划与正文页去规划化

本文面向开发者与验收，说明「先规划、后落笔」工作流的设计动机、各阶段行为与验证结论。文档基线为桌面 **0.2.0** / DSH `0.1.5-rc.2`；该工作流在此基线之后合入。作者侧操作步骤见 [使用者指南](user-guide.md) 的「前置规划」节，本文只保留设计与验收要点，不复制操作步骤。

## 动机

创作顺序明确为：先讨论，再设计人物卡、世界书和大纲 / 章纲，作者确认后落笔。正文页只承担写作；写完后不再要求作者整理本章，避免写作界面出现需要回头维护的章纲、小结或整理动作。

## 各阶段行为

### 规划阶段：讨论与资料设计

- 人物卡一人一份，保存在 `人物卡/`。
- 世界书一词条一份，保存在 `世界书/`。
- 全书大纲、分卷大纲和章纲统一是 `大纲/` 下的普通 Markdown；章纲可以写在总纲对应章节，也可以按作品需要拆到 `大纲/章纲/`。

### 落盘：提案预览与作者确认

规划内容先在对话中讨论。需要落盘时生成可预览提案，作者明确采用后才写入；需要的新目录随采用安全创建。写作助手不能直接改稿；对话中尚未讨论清楚的备选方案不会自动变成作品设定。

### 正文阶段：只承担写作

- 正文页只保留正文编辑、章节导航、字数、保存状态与通用编辑操作。
- 正文页不显示章纲折叠条、章末小结或整理本章；正文右键、标题栏菜单和命令面板不提供写后整理入口。
- 写完正文后不要求补章纲或章末小结；作者主动复盘时仍在对话中讨论并修改对应规划文件。

### 工具边界

- 新工具调用不接受 `chapter_plan`、`chapter_summary`；维护工具只维护作品根 `AGENTS.md`、人物卡和世界书，不写正文 state。
- 旧正文中的 `beats` / `state` 文件头原样保留，只作文件兼容；不自动删除，不继续生成，保存正文时不被删除或覆盖。

## 验收结论

两轮验收均在 2026-09-14 执行，以当前源码的类型检查、相关单元测试和真实界面检查为准；旧的写后整理测试不再作为通过条件。两轮结论均为通过。

### 第一轮：前置规划工作流验收（2026-09-14）

范围：正文页只保留正文编辑、章节导航、字数、保存状态与通用编辑操作；大纲与章纲统一保存到 `大纲/` 下的普通 Markdown；人物卡、世界书和大纲 / 章纲在对话中讨论，经提案预览与作者采用后落盘；写完正文后不出现整理本章，也不要求补章末小结；提案工具拒绝新的 `chapter_plan` / `chapter_summary`；旧作品中的 `beats` / `state` 不迁移、不删除、不改写，仍可安全打开和保存。

### 第二轮：正文页去规划化摩擦验收（2026-09-14）

范围分可见与数据两面。可见面：稿纸底部没有额外规划栏；正文菜单与命令面板没有章纲、章末小结、整理本章；正文切换、保存、补全、选段修改、聊天草稿和焦点行为保持原样。数据面：新章纲只通过 `大纲/` 下的 Markdown 提案创建或修改；正文写入不生成 `beats` / `state`；旧 `beats` / `state` 原样保留；人物卡与世界书的普通维护能力不受影响。

## 自动化闸门

| 闸门 | 覆盖 |
| --- | --- |
| [author-first-gates.spec.ts](../e2e/author-first-gates.spec.ts) | 编辑与维护提示词把章纲引向 `大纲/`；`chapter_plan` / `chapter_summary` 提案被守卫拒绝；记忆工具不得写章节小结 |
| [author-friction-gates.spec.ts](../e2e/author-friction-gates.spec.ts) | 章节切换须等待最新缓冲落盘；保存飞行中继续输入、输入法组字、文档身份变化时禁止离开本章 |

仓库基线 [vitest.config.ts](../vitest.config.ts) 不包含 `e2e/` 下的 spec，两道闸门经专属配置运行：

```powershell
pnpm vitest run --config e2e/author-first-gates.config.ts
pnpm vitest run --config e2e/author-friction-gates.config.ts
```
