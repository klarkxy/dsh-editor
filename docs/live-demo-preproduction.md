# DSH Editor 实机演示：录制前方案

状态：供审阅。尚未录屏或制作成片。品牌宣传片另见 [H3 宣传片方案](h3-promo-preproduction.md)。

## 定位与规格

这支片只回答“DSH Editor 实际怎么用”。画面全部来自当前版本的真实桌面应用；不使用 H3、合成界面或代替真实模型输出的动画。默认约 90 秒、中文、16:9 横版，适合放在产品介绍页或下载页。叙述克制，操作步骤可暂停看清。

演示主线是：打开自己的作品文件夹 → 在稿纸写作 → 与搭档讨论 → 预览改写并由作者应用 → 看见文件与导出入口。让观众看到产品界面和作者掌控改动的过程，不堆砌所有插件功能。

## 90 秒录屏脚本

| 时间 | 真实操作 | 屏幕标注／旁白草稿 | 拍摄要点 |
| --- | --- | --- | --- |
| 0–8 秒 | 首页进入一份专门创建的演示作品。 | “这是 DSH Editor，一款桌面写作应用。” | 只录应用窗口；不露本机用户名、最近真实作品或通知。 |
| 8–23 秒 | 展示文件树、中央稿纸与右侧搭档；在演示文章末尾写入一句话。 | “作品是本地文件夹。写作从稿纸开始。” | 指针慢一点，留出看清三栏的时间。 |
| 23–43 秒 | 在侧栏询问一个具体写作问题，展示真实回复。 | “卡住时，可以先讨论，不必马上改正文。” | 可以剪去等待空白，但保留真实提问与真实结果，不伪造回复。 |
| 43–66 秒 | 选中演示段落，发起选段改写，展示预览，然后由作者点击“应用”。 | “改写先预览。你认可，才写入。” | 保留点击前后状态，让观众看清由谁作决定。 |
| 66–81 秒 | 展示作品文件树和导出入口；如界面能清晰呈现，再展示一次保存状态。 | “稿件留在自己的文件夹，也能导出。” | 不在文件管理器中暴露其他个人文件。 |
| 81–90 秒 | 回到完整稿纸，叠加产品名与下载入口。 | “想看完整用法，就从一份作品开始。” | 片尾链接导出前核对。 |

时间是剪辑目标，真实模型响应速度由录制情况决定。若等待过长，剪掉等待段落并用明显跳切衔接，不把它包装成瞬时生成。

## 演示用文本与提问

只创建一份虚构的非个人演示文章，建议题目为《把十分钟还给阅读》。开头候选：

> 忙碌的一周过后，很多人想在周末读点什么，却常被消息和待办打断。与其等一整块空闲时间，不如先留出十分钟，从一页开始。

讨论提问候选：“这段开头有点平。请给我两个更具体的切入角度，先解释区别，不要直接修改文件。”

选段改写要求候选：“保留原意，让开头更具体、更有画面感；控制在两句话。”

正式录制前用当前产品版本核对入口名称和操作顺序。演示稿只用于拍摄，绝不采用真实用户作品、聊天记录、密钥或私人文件。

## 准备与制作流程

1. 审阅这支演示片的范围和节奏；它与 H3 宣传片分别批准。
2. 获批后创建干净的演示作品，关闭通知，检查窗口尺寸、显示缩放、主题、字体大小和鼠标可见性。
3. 先走通一次真实操作，确认模型连接、预览和导出入口与脚本一致，再录制。保留原始录屏以便核查。
4. 剪辑时只压缩等待和重复操作；用少量局部放大与步骤标题帮助观众读懂界面，不覆盖关键控件。
5. 验收当前版本功能、真实输出、字幕可读性、音量、片尾链接与隐私；导出独立 MP4。

**这支片不调用 H3。** 若宣传片先完成，实机演示可以之后单独制作与发布。
