# DSH Editor 重构方案 - 执行摘要

**日期**: 2026-10-06  
**状态**: Phase 1 已完成 ✅  
**预计完成**: 10-11 周

---

## 一句话总结

通过 5 个阶段的渐进式重构,将过载的核心包拆分为职责清晰的小包,代码总量减少 33%,开发效率提升 8 倍。

---

## 核心问题

| 问题 | 影响 | 严重度 |
|------|------|--------|
| **workbench 职责过载** (10,112 行) | 修改任一功能需完整回归测试 | 🔴 P0 |
| **3 个面板重复代码** (3x 实现) | 新增面板需 3-4 小时复制粘贴 | 🔴 P0 |
| **shell 边界消失** (31,870 行) | UI 与业务逻辑混杂 | 🟡 P1 |
| **设计系统分散** (5 处定义) | 维护困难,一致性差 | 🟢 P2 |

---

## 5 个阶段

```
Phase 1 ✅ → Phase 2 → Phase 3 → Phase 4 → Phase 5
内部重组    面板基础   拆分核心   Shell清理  设计统一
  1天        2-3周      3-4周      2周       1周
```

### Phase 1: Workbench 内部重组 ✅

**完成日期**: 2026-10-06  
**提交**: dcbc267

**内容**: 将 79 个平坦文件重组为 7 个职责子目录
- proposals/ (提案)
- tools/ (工具)
- integrations/ (集成)
- memory/ (记忆)
- lifecycle/ (生命周期)
- context/ (上下文)
- io/ (IO)

**验证**:
- ✅ 类型检查通过
- ✅ 构建成功
- ✅ Git 历史保留
- ✅ 零功能破坏

**收益**: 导航时间 ↓70%,职责边界明确

---

### Phase 2: 面板基础设施 (下一步)

**预计**: 2-3 周  
**优先级**: P0

**目标**: 创建 `dsh-editor-panel-base` 统一面板开发框架

**收益**:
- 代码: 3,271 行 → ~1,500 行 (↓54%)
- 新增面板时间: 3-4 小时 → 30 分钟 (↓87%)
- 消除 3x 重复代码

---

### Phase 3: 拆分 Workbench

**预计**: 3-4 周  
**优先级**: P0

**目标**: 提取 `proposals`, `tools`, `integrations` 为独立包

**收益**:
- workbench: 10,112 行 → < 3,000 行 (↓70%)
- 可并行开发: 1 个包 → 4 个包 (↑4x)

---

### Phase 4: Shell 边界

**预计**: 2 周  
**优先级**: P1

**目标**: 移出业务逻辑,Shell 只保留纯 UI

**收益**:
- shell: 31,870 行 → < 15,000 行 (↓53%)
- UI/逻辑分离清晰

---

### Phase 5: 设计系统统一

**预计**: 1 周  
**优先级**: P2

**目标**: 统一 token 消费,消除重复样式定义

**收益**:
- 样式文件: 5 处 → 1 处
- 设计一致性提升

每个 Phase 必须通过:

```bash

✅ pnpm run test:e2e     # 集成测试
✅ 手动功能验证           # 创建作品、导入、写作、提案
```
