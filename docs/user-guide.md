# DSH Editor 使用者指南

## 从一个本地作品开始

DSH Editor 提供 Windows 便携版 / 安装版和 macOS（Apple Silicon）版的小说写作应用。Windows 可直接双击便携版 EXE，或运行安装器（`Setup.exe`）装到开始菜单；macOS 打开 dmg（或解压 zip）后把应用拖进「应用程序」。首次启动后，可以选择“新建”或“打开作品”。新建作品默认保存在「文档/dsh-editor」下的同名文件夹中；已有作品仍从你选择的本地文件夹打开。

“新建”会要求填写作品名称，然后在「文档/dsh-editor」下建立该文件夹，并放入空的 `正文`、`大纲`、`人物卡`、`世界书` 目录，不会预写总览、总纲、人物索引、设定总汇或首章。同名文件夹已存在时会提示，不会覆盖。资料和章节由你在左侧新建，或由写作搭档按这部作品的需要创建。“打开作品”不会补目录或模板；它会直接显示原有文件树，并让 DSH Agent 阅读现有文本以建立 `.dsh-editor/作品索引.md`。

“打开作品”会直接打开系统目录选择器，选中文件夹后立即进入作品。目录选择器不可用时，可以在路径框里直接输入路径。打开空文件夹时仍可选择“在这里新建”。已有 Markdown 作品直接使用“打开作品”，不会再经过另一套复制式导入入口。

作品打开后，顶部把当前作品名、最近作品切换与「作品」菜单放在同一组控件里。点作品名可在最近作品之间切换；「作品」菜单当前只保留“打开作品 / 新建 / 返回作品列表”三项。存在未保存内容时会先阻止切换或离开。首页“最近”列表仍然可以把入口从列表移除；确认页会再次说明，作品文件、正文、对话和日志都不会删除，以后仍可用“打开作品”重新加入。

主界面默认就是三栏：左侧是 `正文 / 大纲 / 人物卡 / 世界书` 四个分组加组内“新建”的文件树，中间是稿纸编辑器（草稿/补全/选段修改、`‹ ›` 章节导航都在稿纸内部），右侧是写作搭档栏。底部不再有索引状态行；带 `‹ ›` 的章节导航取代了旧的“上一章/下一章”外部按钮。

### 调整工作台布局

顶部“文件”可以折叠或恢复左侧资料栏，“搭档”控制右侧助手栏，“专注”临时只留居中稿纸。两条竖向分隔线可以拖动调整栏宽；聚焦分隔线后也可用左右方向键微调，双击恢复默认宽度。文件栏是否展开及两侧栏宽度会保存在本机界面偏好中。

点击“专注”会暂时隐藏文件栏、搭档栏和调宽线，只保留居中的稿纸；点击“退出专注”后恢复进入前的两侧栏状态，不会关闭对话或丢失未保存内容。

### 常用快捷键

本版本没有专门的快捷键弹窗；只保留下列高频操作，所有快捷键都直接生效，不需要先开对话框：

- `Ctrl+S` 保存当前章节
- `Ctrl+\` 进入或退出专注写作
- `Ctrl+B` 折叠 / 恢复左侧文件栏
- `Ctrl+J` 折叠 / 恢复右侧写作搭档
- `Ctrl+L` 聚焦右侧对话输入框
- `Alt+[` / `Alt+]` 上一章 / 下一章
- `Ctrl+,` 打开 DSH 原生设置弹窗
- 在稿纸内：`Tab` 采纳当前补全建议，`Esc` 放弃补全或改写建议

## 配置接口

首次启动仍可直接进入作品区。顶栏末端的设置控件、写作搭档顶部的“设置接口/模型设置”以及 `Ctrl+,` 打开的是同一个 DSH 原生设置弹窗；其中“模型”分区管理接口、模型与凭据，首次使用引导也由 DSH 处理。密钥只交给 DSH 的私有凭据存储，界面不会读取或回显明文。

“写作”分区只保存编辑器自身的偏好。默认“仅手动”，只有点击稿纸内“补全”时才请求；改为“停顿后提示”后，仅在 `正文` 章节中连续输入并停顿约 1.5 秒时生成一次建议。自动提示不会用于大纲、人物卡或世界书，也不会直接写入，仍需点击“接受补全”或按 `Tab`。

“跨作品作者约定”用于维护不属于某一本书的稳定偏好，例如叙事人称、行文禁忌或协作习惯。最多 1,200 字，保存在本机 DSH 设置中，不会写进作品目录；输入后点击“保存作者约定”。所有作品的搭档、行内补全和选段修改都会参考。旧版浏览器偏好会在首次启动时迁移；迁移失败时原值会继续生效，并可在“写作”分区重试。它不是本书设定，也不会改变文件权限或代替你本轮提出的要求。某一本书独有的规则仍应写入该作品的“项目总览”、人物卡或世界书。

> 导入、归档与 Markdown/TXT 导出当前没有 UI 入口，对应的 workbench RPC（`project.import*`、`archive.*`）仍随桌面 profile 一起发布；不提供入口不等于失去这些能力。快照已有 UI 入口，见下文「提交与回滚」。

## 写作与保存

左侧是一棵普通目录树：文件夹在前、按名称排序，点击行首箭头展开或收起。新建通过右键菜单进行：在任意文件或文件夹行上右键，选择“新建文件 / 新建文件夹”，文件行建在其所在目录、文件夹行建在其内部；在树的空白区域右键则建在根目录。悬停文件夹行尾出现的 `＋` / `▣` 是同样的行内快捷入口。文件名不带扩展名时按 `.md` 创建。所有新建操作都在应用内填写名称，不会再弹出系统输入框。

### 提交与回滚

点侧栏顶部的“提交”会把当前作品存为一次快照，提交说明自动使用当前时间（`YYYY-MM-DD HH:mm`）。点“历史”查看提交列表，任意一条都可以“回滚”：作品内容回到该次提交的状态，回滚前的当前状态会先自动保存为一次新提交，因此回滚本身随时可以撤销。快照只覆盖作品内的 Markdown/TXT 文本；图片等其他文件不会被快照或回滚影响。

正文编辑后约 800 毫秒自动保存，也可以按 `Ctrl+S` 或点击“保存”。

尚未打开文档时，中央稿纸显示与首页相同的封面，并提供“新建文件”。

如果文件同时被其他程序修改，DSH Editor 不会静默覆盖。你可以重新载入磁盘版本，或先保存带时间戳的冲突副本再重新载入；放弃本地草稿前会在工作台内再次确认，取消后草稿原样保留。

临时草稿会帮助恢复意外退出前的内容，但草稿不是备份；重要作品仍应定期复制或纳入版本管理。

### 补全与选段修改

把光标放在正文中并点击“补全”，应用会在当前光标处生成一段建议；建议只显示在稿纸上，不会自动写入。点击“接受补全”或按 `Tab` 才会加入草稿，点击“放弃”或按 `Esc` 则保持正文不变。生成较慢时可以点击“停止补全”。不满意时可点“再来一个”，最多保留三条并用“上一条 / 下一条”比较；新请求失败或返回重复内容时，已有候选不会丢失。

如果在设置里开启“停顿后提示”，只有当前稿纸仍聚焦、光标没有选中文字、光标前已有足够正文且本次编辑尚未提示过时才会请求。继续输入、切换文档、出现版本冲突或已有建议时都会取消旧计时；失败不会在没有新输入时循环重试。

选中文字后点击“修改选段”，稿纸会并排显示原文与修改后内容。点击“应用修改”或按 `Ctrl+Enter` 才会替换原选区；点击“放弃”不会修改正文。生成期间继续输入或切换文档会立即停止旧请求，避免把过期结果写进新内容。

### 查找、导航与文件整理

本版本没有全文搜索面板；想跨章节找一段文字时仍可用 `Alt+[` / `Alt+]` 逐章切换，或直接用 OS 的“在文件夹中查找”。`search.text` RPC 随 `dsh-manuscript` 继续发布，未来可重新挂到 UI。

稿纸顶部的 `‹ ›` 按完整 `正文` 目录自然排序切换章节，即使文件夹尚未在树中展开也不会漏章。存在未保存内容或版本冲突时，章节切换会暂停，避免丢失当前编辑。

在文件树中右键任意文件或文件夹，会弹出操作菜单：新建文件 / 新建文件夹、复制、剪切、粘贴、重命名、删除。复制 / 剪切先把条目放进内部剪贴板，再到目标目录（或其中任意一行）的右键菜单里“粘贴”；复制的条目可以反复粘贴，剪切粘贴一次后剪贴板自动清空。复制遇到同名会自动改名（如 `第一章 2.md`），移动和重命名遇到同名会提示并取消。删除会先在确认框说明不可撤销（除非之前已提交到历史），确认后删除该文件或整个文件夹。归档入口本版本仍不提供；`archive.*` 随 workbench Host 保留。

## 使用写作助手

右侧可以自由讨论剧情、人物、设定和文字。每次发送时，应用会按固定顺序带上有界的项目总览、总纲、人物索引、设定总汇和（如已存在）作品索引；单份最多 4,000 字符、合计最多 12,000 字符。除此之外，应用会用本次请求、当前文档路径和当前文档已保存内容匹配 `世界书` 内的设定；按优先级带入匹配项，单份最多 3,000 字符、合计最多 6,000 字符，不会挤占固定资料。

在 `世界书` 里新建的文件默认按文件名自动派生触发词；需要显式控制时可自己写上 YAML frontmatter，格式没有变：

```yaml
---
triggers: [港口, 海关]
enabled: true
priority: 8
---
```

`triggers` 支持行内列表或逐行列表，按字面包含匹配；`priority` 越高越先纳入。本版本没有专门的可视化触发词编辑界面，配置只能手工写在文件头；显式但损坏的 frontmatter 会让匹配自动跳过，避免把未知字段或注释读进提示。文件正文不会被界面覆盖。

没有 frontmatter 的旧世界书仍会用文件名作为触发词；停用、超出扫描限制或读取失败的文件不会进入提示。消息下方的“项目上下文”可展开查看固定资料、触发世界书、匹配来源、截断情况和扫描计数，但不会展示资料原文。固定资料缺失或单个世界书读取失败不会阻止发送；如果整个上下文编译失败，消息不会送出，输入内容会保留供重试。写作助手仍可在当前作品中进一步查找并阅读 Markdown 资料。

讨论、构思、写作、审读可以在同一段对话里自然切换，不需要选择工作模式。写作助手会在有帮助时静默参考内置的小说创作经验；这些参考不会覆盖你的正文、设定或当次要求。

如果已经填写跨作品作者约定，每条消息的“项目上下文”摘要会显示本次带入的约定字符数，但不会在对话气泡中重复展示约定原文。约定与本轮请求、项目资料在结构上分开；历史对话仍能按原格式读取。

写作助手不能直接改稿。它提出文件修改时，界面会显示原文与修改后内容，或新文件内容。只有点击“应用”后才会写入；点击“忽略”不会产生任何修改。如果文件已经变化，旧建议会失效，避免覆盖新内容。

搭档栏顶部可以切换当前作品已有的对话，也可以用铅笔按钮在应用内修改对话名称。存在尚未发送的输入时，切换对话、新建对话或返回作品列表前都会在工作台内确认；取消后输入和当前对话原样保留。打开设置是覆盖层，不会丢弃输入。不同对话的草稿和发送状态不会混在一起。没有手工命名的新对话会在第一条助手回复出现后生成简短名称，手工名称始终优先。当前版本不提供对话归档或删除入口，以免产生无法从界面恢复的隐藏对话。

点击“新对话”后先选择本次使用的模型，再开始一段新的讨论。当前对话顶部也会显示它正在使用的模型。输入消息时按 `Enter` 发送，按 `Shift+Enter` 换行；中文输入法还在组合文字时不会误发送。底层工具名称、调用参数和原始错误不会显示在产品界面中。

## 导出

本版本没有 UI 内的“导出 Markdown / TXT”入口；`search.text` / 章节导航仍可拿到完整顺序和文本，但 `全文导出` 入口刻意未挂。需要整书出稿时，可直接在 `正文` 目录外复制 `.md` / `.txt`，或继续等未来重新挂回的导出操作；底层 workbench 不会替你拼合章节。

## 更新与回滚

顶栏的“关于”按钮打开“关于 DSH Editor”对话框：显示当前版本，并可以从 GitHub Releases 检查新版本；发现新版时会给出发布说明和“前往下载”。应用不会自动更新：Windows 便携版下载新版 EXE 手动替换，安装版运行新版安装器覆盖安装，macOS 下载新版 dmg/zip 后替换「应用程序」中的应用。更新前先保存作品并关闭旧版本。保留旧版本和它的 SHA-256 作为回滚点；如需回滚，关闭新版后重新运行旧版本。当前版本没有代码签名：Windows SmartScreen 可能提示未知发布者，macOS 首次打开需在访达中右键应用并选择“打开”。请只运行可信来源的文件。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 无法连接模型 | 检查接口地址、Key、额度和网络，再重新连接。 |
| 保存冲突 | 重新载入磁盘版本，或先另存冲突副本。 |
| 建议无法应用 | 文件已经变化；让写作助手根据最新内容重新提出建议。 |
| 想恢复归档或导出现稿 | 本版本没有 UI 入口；可在 workbench RPC 恢复，或把 `正文/` 直接拷出。 |
| 主题不对 | 顶栏切换 paper / ink；选择会写入 `localStorage["dsh-editor.theme"]`，首次进入还会参考系统 `prefers-color-scheme`。 |
| 想找正文中的某段文字 | 章节用 `Alt+[` / `Alt+]` 翻；跨章节搜索请用 OS 文件搜索，本版本未挂搜索面板。 |
| SmartScreen 警告 | 当前便携版未签名；核对可信来源和 SHA-256。 |
| 启动后不是写作界面 | 保存截图和诊断信息并联系开发者。 |
