# 搭档对话（bot 化）设计

作者不管理会话。每部作品只有一个搭档：打开作品就能直接写，长对话、换模型、缓存过期都由产品在背后处理。本文记录取舍；字段、阈值与实现以代码为准。

## 形态

- 一部作品一个搭档。背后是一串 DSH 会话（段），作品元数据 `.dsh-editor/bot.json` 只记录指针：当前段、历史段顺序、待用的交接与回顾。会话、消息、模型与审批仍以 DSH 为唯一权威，Editor 不复制会话内容。
- 界面没有会话列表、新建按钮、模式菜单或开发者模式。历史段按顺序拼在当前段之上，只读显示；每次换段留一条淡标记。
- 只有一个标准写作 preset。小说、文章、技术文档的写法是同一 preset 下的 skills，由模型按作品目录与作者的话选用；目录约定不预建。
- 旧版按模式绑定的会话不迁移、不展示，数据留在 DSH 中。

## 开场

- 空作品：搭档用固定文案询问想写什么，不调用模型；作者回复时才建会话。
- 已有内容的作品：首次接入时做一次有上限的初始化（目录树、大纲、人物卡、世界书、最近章节的标题与开头），以一条简短的作品认识作为开场。该认识只属于搭档的工作上下文，随交接传递，不写入 `AGENTS.md`：规则类内容只来自作者的明确表述。

## 换段

换段是唯一的上下文管理手段。凡会让提示词缓存失效的变化都换段：

| 触发 | 时机 |
| --- | --- |
| 闲置超过缓存有效期 | 作者下一次发送前 |
| 换模型 | 选择后立即（两轮之间） |
| 系统提示词输入变化（作者约定、审查豁免） | 作者下一次发送前 |
| 一轮结束时上下文超过可用窗口约 70% | 该轮结束后 |
| 模型判断话题告一段落并调用收尾工具 | 该轮结束后 |

不触发：记忆、人物卡、世界书写入（模型用工具读最新文件），作者改正文。

换段只在两轮之间进行，且没有待审批、待回答的请求。交接内容按固定顺序取得，前一步不可用才进入下一步：

1. 整段对话足够短（约 16K token）：原文全部带入，不写摘要。
2. 已存的交接覆盖到最新内容：直接使用。
3. 用当前段的模型、沿用同一请求前缀写摘要（命中缓存），附最近几轮原文，作者原话不改写。
4. 摘要失败：只带最近几轮原文（按目标模型窗口截取），并提示更早历史可用回读工具查询。

随后新建会话、写入交接、移动指针、留下标记。新会话本身建不成时保留当前段，下次触发时重走同一流程。

一轮进行中上下文逼近上限无法换段，由 DSH 原地压缩兜底（约 90%）。

## 闲置回顾

作者闲置达到设定时间（默认 15 分钟，表示真正离开了电脑）时，在缓存仍有效的窗口内用同一前缀做一次增量摘要，同时得到两部分：给作者的回顾卡片（做了什么、当前进度、待处理、下一步）与给模型的交接。回顾显示在时间线上；交接先存着，不立即换段。作者在缓存有效期内回来就继续当前段；真正需要换段时直接取用，不必等待。应用关闭期间不做后台摘要。

## 缓存

- 设置提供「闲置回顾时间」（默认 15 分钟）与「缓存有效期」（默认 1 小时，可设为永不失效），前者须小于后者。
- 写作中长考常超过 5 分钟，Editor 写入的供应商默认使用长缓存（`cacheRetention: long`，Anthropic 协议为 1 小时档）；作者显式设置的值保留。长缓存写入单价更高、读取仍便宜，按写作节奏整体更省。DeepSeek 自动缓存，不受此项影响。

## 系统提示词冻结

系统提示词中会变化的输入在段开始时固定，中途改动从下一段生效，并作为换段触发。会话期间需要最新内容时，模型用工具读取文件。

## 回读

模型用回读工具搜索本作品各段的原始消息（含被原地压缩的部分），只能访问本作品的段。中文搜索按字面逐字扫描，不依赖分词全文索引：DSH 的 `unicode61` 分词把连续汉字视为一个词，短词查不到。

## 暂缓

- 插件推荐与对话内找插件：在本设计落地后进行；装插件后工具变化按换段处理。
- 以 diff 审查取代文件提案：已随直接写入落地——搭档按作者要求直接改正文与大纲，对话留可定位、可撤销的记录，作者正在编辑的文件拒绝写入。提案板与「待处理提案推迟换段」已移除。
